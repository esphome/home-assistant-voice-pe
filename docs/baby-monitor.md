# Экспериментальная радионяня Voice PE

Это пробный режим передачи звука, не сертифицированное устройство наблюдения.
Прошивка полностью скомпилирована; приём и авторизованное прослушивание проверены
с синтетическим PCM. Длительная работа и звук на физическом Voice PE требуют испытания. Обычный пакет не включает радионяню:
её нужно подключить отдельно. Custom-Dialog-UI не используется.

## Как устроено

Voice PE → TCP-порт HA → авторизованный WebSocket HA → карточка на телефоне.
PCM: mono, signed 16-bit little-endian, 16 кГц, канал 0 микрофонного тракта.
Звук хранится только в кратком буфере памяти, на диск не записывается.
Ориентир задержки — несколько сотен миллисекунд; реальную задержку нужно измерить.
Слушать могут до четырёх вошедших в HA пользователей одновременно.

Устройство использует отдельный ключ **только для отправки аудио**. Он не даёт
доступа к HA или прослушиванию. Прослушивание доступно вошедшим пользователям HA,
включая пользователей без прав администратора; отдельных прав на комнаты пока нет.
TCP между колонкой и сервером в этом прототипе **не зашифрован**: ключ и аудио
передаются внутри доверенной домашней сети. Не публикуйте TCP-порт в интернет.
При доступе к HA по HTTPS карточка использует существующее защищённое соединение HA.

## 1. Интеграция Home Assistant (Docker)

1. Скопируйте каталог `custom_components/voice_pe_monitor` из этого репозитория
   в `/config/custom_components/voice_pe_monitor` **внутри контейнера HA**.
   Обычно `/config` — примонтированный каталог конфигурации на Docker-хосте.
2. Перезапустите Home Assistant.
3. Настройки → Устройства и службы → Добавить интеграцию → **Voice PE Monitor**.
4. Укажите `node_id`, точно равный ESPHome `name`, например
   `home-assistant-voice-0ab77d`. Скопируйте с формы предлагаемый ключ до нажатия
   «Отправить». Запишите его в ESPHome `secrets.yaml`:

   ```yaml
   baby_monitor_upload_key: "СКОПИРОВАННЫЙ_КЛЮЧ_ИЗ_ФОРМЫ"
   ```

   Не используйте долгоживущий токен HA. Не публикуйте файл secrets.yaml в GitHub.
5. TCP-порт по умолчанию — **8124**. Если HA запущен с `network_mode: host`,
   Docker-проброс не нужен. При bridge-сети добавьте публикацию `8124:8124/tcp`
   в существующий compose-сервис HA и пересоздайте контейнер.
   Разрешите доступ к этому порту от колонки в локальном firewall.
6. Для каждой дополнительной колонки создайте отдельную запись интеграции с
   отдельным ключом и портом (8125, 8126…), пробросьте соответствующий порт.

Смена ключа в этой версии: удалить запись интеграции и добавить заново,
затем обновить ключ в ESPHome и перепрошить колонку.

## 2. ESPHome: подключить дополнительный пакет

Оставьте текущий пакет с голосом и часами. Добавьте второй файл в его `files`:

```yaml
substitutions:
  name: home-assistant-voice-0ab77d
  friendly_name: Home Assistant Voice 0ab77d
  baby_monitor_host: "192.168.31.83"  # IPv4 Docker-хоста HA, не адрес браузера
  baby_monitor_port: "8124"

packages:
  voice_pe:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: experimental/baby-monitor
    files:
      - home-assistant-voice.yaml
      - modules/baby-monitor.yaml
    refresh: always

esphome:
  name: ${name}
  name_add_mac_suffix: false
  friendly_name: ${friendly_name}

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
```

Скомпилируйте и установите обновление. Появятся переключатель **Радионяня**
и бинарный датчик **Радионяня: передача звука**. После перезагрузки режим
всегда выключен. Включение при активном Mute запрещено.

## 3. Карточка HA

Настройки → Панели управления → меню → Ресурсы → Добавить ресурс:
`/voice_pe_monitor/monitor-card.js`, тип **JavaScript module**.
В YAML-режиме ресурсов добавьте его в `lovelace.resources` существующей конфигурации.
Затем добавьте ручную карточку:

```yaml
type: custom:voice-pe-monitor-card
node_id: home-assistant-voice-0ab77d
title: Детская
# Необязательно: реальный entity_id переключателя «Радионяня» со страницы колонки.
switch_entity: switch.home_assistant_voice_0ab77d_radioniania
```

Уточните `switch_entity` в HA, не копируйте пример вслепую: имя зависит от
идентификаторов HA. Без него включайте переключатель на странице устройства.
На телефоне нажмите **Слушать**: браузеру нужен явный клик для воспроизведения.
Включите **Радионяня** на колонке. Карточка покажет статус источника.

- Оранжевое кольцо показывает **включённый режим**, даже если приёмник недоступен.
- Бинарный датчик показывает подтверждённое соединение и захват микрофона.
- Голосовой ассистент и wake word приостановлены на время режима.
- Аппаратный или программный Mute выключает режим и разрывает аудиосоединение.
  Снятие Mute не включает радионяню повторно.
- Потеря подключения ESPHome API тоже выключает режим (проверка раз в 250 мс).
- **Остановить** в карточке прекращает только прослушивание на этом телефоне.
  Для прекращения отправки звука выключите **Радионяня** или включите Mute.
- Переключатель LED Ring не скрывает индикацию активной радионяни.
- После выключения режима возобновляется обычная работа ассистента.
- Блокировка телефона/уход со страницы может остановить звук. Фоновое
  прослушивание на мобильных браузерах не гарантируется.

## Первая проверка

1. Проверьте голос и часы с выключенной радионяней.
2. Включите радионяню: кольцо оранжевое, датчик передачи включился, карточка слышит.
3. Переведите физический Mute: поток и режим должны выключиться. Повторите с
   программным Mute. Небольшой уже полученный браузером буфер может доиграть.
4. Снимите Mute: режим не должен включиться сам. Проверьте обычный голос.
5. Остановите HA или разорвите сеть: поток должен остановиться без зависания
   устройства. Восстановите HA и проверьте, нужно ли включить режим вручную.
6. Прослушайте 10–15 минут и проверьте задержку, обрывы и нагрев.

Локальные проверки разработчика:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
/workspace/.cache/ha-monitor-venv/bin/python -m unittest discover -s tests -p 'test_baby_monitor_ha.py'
node --test tests/test_baby_monitor_card.cjs
```

Серверная часть проверена на HA Core 2025.1.4 (Python 3.12); прошивка —
ESPHome 2026.9.0, ESP-IDF 5.5.5, ESP32-S3. Проверка с версией HA пользователя
и физической колонкой остаётся обязательной перед длительным использованием.
