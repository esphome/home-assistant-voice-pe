# Экспериментальная радионяня Voice PE

Это пробный режим передачи звука, не сертифицированное устройство наблюдения.
Прошивка полностью скомпилирована; приём и авторизованное прослушивание проверены
с синтетическим PCM. Длительная работа и звук на физическом Voice PE требуют испытания. Обычный пакет не включает радионяню:
её нужно подключить отдельно. Custom-Dialog-UI не используется.

## Как устроено

Voice PE → TCP-порт HA → авторизованный WebSocket HA → карточка на телефоне.
PCM: mono, signed 16-bit little-endian, 16 кГц, канал 0 микрофонного тракта.
Звук хранится только в кратком буфере памяти, на диск не записывается.
Ориентир задержки — несколько сотен миллисекунд; реальную задержку нужно измерить.
Слушать могут до четырёх вошедших в HA пользователей одновременно.

Устройство использует отдельный ключ **только для отправки аудио**. Он не даёт
доступа к HA или прослушиванию. Прослушивание доступно вошедшим пользователям HA,
включая пользователей без прав администратора; отдельных прав на комнаты пока нет.
TCP между колонкой и сервером в этом прототипе **не зашифрован**: ключ и аудио
передаются внутри доверенной домашней сети. Не публикуйте TCP-порт в интернет.
При доступе к HA по HTTPS карточка использует существующее защищённое соединение HA.

## 1. Интеграция Home Assistant (Docker)

1. Скопируйте каталог `custom_components/voice_pe_monitor` из этого репозитория
   в `/config/custom_components/voice_pe_monitor` **внутри контейнера HA**.
   Обычно `/config` — примонтированный каталог конфигурации на Docker-хосте.
2. Перезапустите Home Assistant.
3. Настройки → Устройства и службы → Добавить интеграцию → **Voice PE Monitor**.
4. Укажите `node_id`, точно равный ESPHome `name`, например
   `home-assistant-voice-0ab77d`, и порт. **Ключ не нужно вводить или копировать**:
   HA создаёт его сам и передаёт колонке через её существующее ESPHome API
   подключение. Для этого нужны интеграция 0.3.0 и обновлённая прошивка.
5. TCP-порт по умолчанию — **8124**. Если HA запущен с `network_mode: host`,
   Docker-проброс не нужен. При bridge-сети добавьте публикацию `8124:8124/tcp`
   в существующий compose-сервис HA и пересоздайте контейнер.
   Разрешите доступ к этому порту от колонки в локальном firewall.
6. Для каждой дополнительной колонки создайте отдельную запись интеграции с
   отдельным портом (8125, 8126…), пробросьте соответствующий порт.

Существующие записи интеграции переустанавливать не нужно: их ключи сохраняются
и передаются автоматически. Новые записи получают случайный ключ в HA.
Из `secrets.yaml` можно удалить старый `baby_monitor_upload_key`, а из пользовательского
YAML — его упоминания. Без полученных от HA настроек захват для радионяни не запускается.
Ключ на колонке хранится только в памяти и повторно передаётся после подключения,
перезагрузки, включения переключателя или запуска через сценарий HA.

## 2. ESPHome: подключить дополнительный пакет

Оставьте текущий пакет с голосом и часами. Добавьте второй файл в его `files`:

```yaml
substitutions:
  name: home-assistant-voice-0ab77d
  friendly_name: Home Assistant Voice 0ab77d
  baby_monitor_port: "8124"

packages:
  voice_pe:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: experimental/baby-monitor
    files:
      - home-assistant-voice.yaml
      - modules/baby-monitor.yaml
    refresh: always

esphome:
  name: ${name}
  name_add_mac_suffix: false
  friendly_name: ${friendly_name}

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
```

Адрес HA вручную не требуется: по умолчанию `baby_monitor_host: "auto"`.
При подключении клиента **Home Assistant** через ESPHome API колонка запоминает
его IPv4-адрес в памяти и использует его для отправки аудио. Подключение
ESPHome Device Builder/просмотра логов этот адрес не заменяет. После смены IP
или перезагрузки адрес изучается заново; перед подтверждением ключа захват
микрофона не начинается. TCP-порт и ключ отправки остаются прежними.

Если в старом YAML есть `baby_monitor_host: "192.168..."`, удалите строку или
замените её на `baby_monitor_host: "auto"`. Явно заданный IPv4 всегда имеет
приоритет и не меняется автоматически. При проксировании ESPHome API, сложной
маршрутизации или подключении HA к ESPHome только по IPv6 задайте IPv4
Docker-хоста HA вручную: `baby_monitor_host: "192.168.31.83"`.
В Docker bridge TCP-порт по-прежнему нужно опубликовать на Docker-хосте.

Скомпилируйте и установите обновление. Появятся переключатель **Радионяня**
и бинарный датчик **Радионяня: передача звука**. После перезагрузки режим
всегда выключен. Включение при активном Mute запрещено.

## 3. Карточка HA

Настройки → Панели управления → меню → Ресурсы → Добавить ресурс:
`/voice_pe_monitor/monitor-card.js`, тип **JavaScript module**.
В YAML-режиме ресурсов добавьте его в `lovelace.resources` существующей конфигурации.
Затем добавьте ручную карточку:

```yaml
type: custom:voice-pe-monitor-card
node_id: home-assistant-voice-0ab77d
title: Детская
# Необязательно: реальный entity_id переключателя «Радионяня» со страницы колонки.
switch_entity: switch.home_assistant_voice_0ab77d_radioniania
```

Уточните `switch_entity` в HA, не копируйте пример вслепую: имя зависит от
идентификаторов HA. Без него включайте переключатель на странице устройства.
На телефоне нажмите **Слушать**: браузеру нужен явный клик для воспроизведения.
Включите **Радионяня** на колонке. Карточка покажет статус источника.

- Оранжевое кольцо показывает **включённый режим**, даже если приёмник недоступен.
- Бинарный датчик показывает подтверждённое соединение и захват микрофона.
- Голосовой ассистент и wake word приостановлены на время режима.
- Аппаратный или программный Mute выключает режим и разрывает аудиосоединение.
  Снятие Mute не включает радионяню повторно.
- Потеря подключения ESPHome API тоже выключает режим (проверка раз в 250 мс).
- **Остановить** в карточке прекращает только прослушивание на этом телефоне.
  Для прекращения отправки звука выключите **Радионяня** или включите Mute.
- Переключатель LED Ring не скрывает индикацию активной радионяни.
- После выключения режима возобновляется обычная работа ассистента.
- Блокировка телефона/уход со страницы может остановить звук. Фоновое
  прослушивание на мобильных браузерах не гарантируется.

## Первая проверка

1. Проверьте голос и часы с выключенной радионяней.
2. Включите радионяню: кольцо оранжевое, датчик передачи включился, карточка слышит.
3. Переведите физический Mute: поток и режим должны выключиться. Повторите с
   программным Mute. Небольшой уже полученный браузером буфер может доиграть.
4. Снимите Mute: режим не должен включиться сам. Проверьте обычный голос.
5. Остановите HA или разорвите сеть: поток должен остановиться без зависания
   устройства. Восстановите HA и проверьте, нужно ли включить режим вручную.
6. Прослушайте 10–15 минут и проверьте задержку, обрывы и нагрев.

Локальные проверки разработчика:

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
/workspace/.cache/ha-monitor-venv/bin/python -m unittest discover -s tests -p 'test_baby_monitor_ha.py'
node --test tests/test_baby_monitor_card.cjs
```

Серверная часть проверена на HA Core 2025.1.4 (Python 3.12); прошивка —
ESPHome 2026.9.0, ESP-IDF 5.5.5, ESP32-S3. Проверка с версией HA пользователя
и физической колонкой остаётся обязательной перед длительным использованием.


## Прослушивание на второй колонке и запуск сценариями HA

Обновите интеграцию до 0.3.0 (скопируйте каталог заново и перезапустите HA).
На **обеих** колонках нужна прошивка этой экспериментальной ветки с пакетом
`modules/baby-monitor.yaml`. Каждая колонка, которую выбираете источником,
должна быть добавлена в Voice PE Monitor со своим `name` и TCP-портом.
Для колонки, работающей только слушателем, запись приёмника в HA не обязательна.
**Ни на источнике, ни на слушателе ключ в ESPHome YAML не нужен.**

Появятся действия HA:

- `voice_pe_monitor.start_source` — включить передачу с выбранной колонки.
- `voice_pe_monitor.start_listener` — выбрать источник и колонку, где слушать.
- `voice_pe_monitor.stop` — остановить всю пару по ID любой её колонки.

В UI действий есть выбор устройств ESPHome. В YAML нужны именно **device ID**
из HA, не entity ID и не MAC. Их можно выбрать в визуальном редакторе, затем
перейти в YAML. Пример сценария запуска пары (замените ID обеих колонок):

```yaml
alias: Слушать детскую на второй колонке
mode: single
sequence:
  - action: voice_pe_monitor.start_source
    data:
      device_id: f78b84553b463617269c25293950bb55
  - action: voice_pe_monitor.start_listener
    data:
      source_device_id: f78b84553b463617269c25293950bb55
      device_id: DEVICE_ID_ВТОРОЙ_КОЛОНКИ
      ha_url: "http://192.168.31.83:8123"
```

`start_source` ждёт подтверждения TCP-подключения до 10 секунд. Если подключения
нет (например, Mute включён), действие завершится ошибкой и выключит источник.
`start_listener` ждёт HTTP-подключения слушателя до 12 секунд. При отмене кнопкой
во время запуска действие завершится ошибкой и выключит пару.
`ha_url` — адрес HA, доступный второй колонке; можно пропустить при корректно
настроенном внутреннем URL HA. При Docker bridge явно укажите IP Docker-хоста,
а не внутренний IP контейнера. Источник и слушатель должны быть разными устройствами.
Чтобы поменять пару или роли, сначала остановите текущую пару.

Отдельно включить только источник для карточки телефона:

```yaml
action: voice_pe_monitor.start_source
data:
  device_id: f78b84553b463617269c25293950bb55
```

Остановить из другого сценария:

```yaml
action: voice_pe_monitor.stop
data:
  device_id: DEVICE_ID_ЛЮБОЙ_КОЛОНКИ_ПАРЫ
```

**Короткое нажатие верхней кнопки любой колонки выключает обе колонки пары**:
источник закрывает TCP, слушатель закрывает HTTP-воспроизведение, а HA завершает
сессию и отправляет остановку обоим устройствам. Кнопка в этом режиме не
запускает новый диалог с ассистентом. Без пары кнопка останавливает локальный режим.

Кольцо источника оранжевое, слушателя — розовое. Ассистент и wake word временно
приостановлены на обоих устройствах. После остановки возобновляется обычное
распознавание, сохраняется прежнее состояние Mute и громкость. Если до запуска
слушателя играла музыка, она приостанавливается и при остановке возобновляется;
сторонние объявления на этом этапе могут прервать прослушивание и закончить пару.
На обеих колонках режим после перезапуска выключен. При потере HA локальное
выключение кнопкой работает сразу; удалённое выключение зависит от связи,
а слушатель дополнительно выходит из режима после окончания/ошибки потока.

Звук идёт через HA, а не напрямую между колонками. Для слушателя HA создаёт
непредсказуемый одноразовый URL, действующий 15 секунд до первого подключения;
после закрытия потока он отзывается. URL позволяет только чтение выбранного
аудиопотока и не является токеном пользователя HA. На колонке используется
отдельный HTTP-декодер с буфером 8192 байта; обычный буфер TTS не меняется.
WAV-декодирование добавлено в прошивку явно. Звук по локальному HTTP не шифруется;
для HTTPS нужен доступный и доверенный колонке сертификат HA.

Проверки разработчика пары:

```sh
/workspace/.cache/ha-monitor-venv/bin/python -m unittest discover -s tests -p 'test_baby_monitor_pair.py'
```

Программно проверяются адресация по device ID, реальный TCP → HTTP WAV,
одноразовость ссылки и остановка обеих сторон при разрыве соединения с любой
стороны. Воспроизведение и задержку нужно отдельно проверить на двух физических
Voice PE.

## Цвет и яркость кольца

В HA откройте светильник **LED Ring**: в обычном режиме ожидания доступны
включение, выключение, цвет и яркость кольца. Будильники, таймеры, Mute и
состояния ассистента временно показывают свою индикацию; после неё возвращаются
настройки светильника. При радионяне источник оранжевый, слушатель розовый.
Яркость радионяни берётся из настройки LED Ring (минимум 5%, чтобы индикация
включённого микрофона или слушателя оставалась видимой). Выключение светильника
не скрывает активную радионяню; для выхода нажмите верхнюю кнопку.
