# Home Assistant Voice PE с часами MAX7219

Прошивка для Home Assistant Voice: Preview Edition с напрямую подключённой
матрицей MAX7219. Отдельная ESP32 для часов не нужна. Голосовой помощник,
микрофон, динамик и световое кольцо работают в той же прошивке.

Оригинальные материалы: [Voice PE](https://www.home-assistant.io/voice-pe/),
[документация устройства](https://voice-pe.home-assistant.io/),
[заводской установщик](https://esphome.github.io/home-assistant-voice-pe/).

## Озвучивание напоминаний

Прошивка предоставляет действие ESPHome `<имя_устройства>_reminder_announce`
с обязательным полем `url` — доступной колонке HTTP(S)-ссылкой на речь.
HA Dialog UI передаёт эту ссылку после синтеза текста выбранным TTS.
Само устройство воспроизводит встроенный короткий сигнал
`center_button_double_press_sound`, а затем речь в одной очереди announcement.
Звуковой файл с HA передавать не требуется. Сигнал уже находится в прошивке.

Напоминания ждут окончания текущего будильника, голосового ответа или другого
объявления. Несколько напоминаний выполняются последовательно (очередь до 8).
Для этого поведения требуется установить обновлённую прошивку на колонку.

## Подключение

Подключайте провода к стороне **IN** панели, а не OUT.

| Вход MAX7219 | Контакт Voice PE |
| --- | --- |
| DIN | IO41 |
| CLK | IO40 |
| CS / LOAD | IO42 |
| VCC | Питание 5 В |
| GND | Общая земля GND |

Для надёжного согласования сигналов 3,3 В и MAX7219 с питанием 5 В используйте
74AHCT125 или подходящий аналог. Питание подбирайте с учётом потребления панели
и Voice PE. Проверяйте проводку при отключённом питании.

## Конфигурация ESPHome: две матрицы 8×8

В ESPHome Device Builder откройте YAML вашей **Voice PE** и используйте этот
пакет. Сохраните собственные параметры API, шифрования и другие локальные
настройки, если они уже заданы. В примере замените имя устройства на своё.

```yaml
substitutions:
  name: home-assistant-voice-0ab77d
  friendly_name: Home Assistant Voice 0ab77d

packages:
  voice_pe:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: dev
    files:
      - home-assistant-voice.yaml
    refresh: always

esphome:
  name: ${name}
  name_add_mac_suffix: false
  friendly_name: ${friendly_name}

wifi:
  ssid: !secret wifi_ssid
  password: !secret wifi_password
```

В локальном `secrets.yaml` должны быть `wifi_ssid` и `wifi_password`.
Сохраните конфигурацию и установите прошивку через **Install → Wirelessly**.
`refresh: always` позволяет получать свежие изменения ветки `dev` при сборке.

| Устройство | Файл в `packages → voice_pe → files` |
| --- | --- |
| Voice PE + две матрицы, 16×8 (основной вариант) | `home-assistant-voice.yaml` |
| Voice PE + три матрицы, 24×8 | `home-assistant-voice.yaml` + `max7219_num_chips: "3"` |
| Voice PE без дисплея | `home-assistant-voice.base.yaml` |

Старые файлы `home-assistant-voice.max7219-2panel.yaml` и
`home-assistant-voice.max7219.yaml` удалены. В существующем YAML замените их
на `home-assistant-voice.yaml`.

Выбирайте **один** из этих файлов. Не добавляйте базовую прошивку повторно:
варианты с часами уже включают её и сохраняют запуск усилителя динамика.
Назначение пинов можно переопределить в `substitutions`:

```yaml
  max7219_din_pin: GPIO41
  max7219_clk_pin: GPIO40
  max7219_cs_pin: GPIO42
```

## Время, таймеры и будильники

1. Добавьте Voice PE в интеграцию **ESPHome** в Home Assistant.
2. В интеграции **Время и дата / Time & Date** включите датчик `sensor.time`.
3. Для таймеров и будильников обновите
   [HA Dialog UI](https://github.com/mikhailhimei/ha-dialog-ui)
   и перезапустите Home Assistant.
4. Проверьте наличие `sensor.ha_dialog_ui_timers` и
   `sensor.ha_dialog_ui_alarm`, у обоих должен быть атрибут `payload`.

`payload` содержит список записей. Прошивка сама преобразует передаваемое
Home Assistant Python-представление списка в JSON; `payload_json` не нужен.
Таймер выбирается интеграцией как последний созданный оставшийся таймер каждого
устройства, а прошивка находит свою запись по `device_id` или `media`, независимо
от порядка списка.

В репозитории по умолчанию указана колонка автора. Для другой колонки добавьте
в существующий блок `substitutions` её идентификатор устройства Home Assistant
и сущность медиаплеера:

```yaml
  dialog_timer_device_id: "ID_УСТРОЙСТВА_В_HOME_ASSISTANT"
  dialog_timer_media_entity: "media_player.ВАША_КОЛОНКА"
```

При других именах датчиков также задайте `dialog_timer_entity` и
`dialog_alarm_entity`. Используйте именно **entity_id**, а не отображаемое имя.
Если HA сохранил старые имена после обновления интеграции, укажите их явно:

```yaml
  dialog_timer_entity: sensor.dialog_custom_ui_timers
  dialog_alarm_entity: sensor.dialog_custom_ui_alarm
```

Совпадения `device_id` достаточно, даже если сущность медиаплеера была
переименована. После изменения подписок на сенсоры пересоберите и установите
прошивку, затем создайте новый таймер для проверки.

Поведение дисплея:

- Без таймера отображается время `HH:MM`.
- При остатке таймера **60:00 и больше** остаются часы с точкой будильника.
- На **59:59** начинается обратный отсчёт `MM:SS`; пауза останавливает его.
- В режиме часов точка также показывает включённый будильник этой колонки.
- Без полученного времени и короткого таймера отображается `--:--`.

Время срабатывания будильника не выводится: текущий `payload` передаёт его
статус, но не время. В мини-версии используются цифры 3×5, прямая единица и одно
двоеточие. Настройка **«Яркость часов»** доступна на странице устройства.

После загрузки дисплей выполняет двухсекундный тест. Повторить его можно кнопкой
**«Проверка матрицы»**. Если нет ни кнопки, ни настройки яркости, проверьте, что
собран именно пакет с часами. Если тест не зажигает панель, проверяйте питание,
сторону IN, общую землю, уровни сигналов и соответствие проводов заданным GPIO.

## Текст и иконки из автоматизации

После обновления прошивки действие появится в **Инструменты разработчика →
Действия**. Его имя зависит от имени устройства; выберите действие `matrix_show`
вашей колонки. Пример текста:

```yaml
action: esphome.home_assistant_voice_0ab77d_matrix_show
data:
  message: "Привет"
  icon: ""
  duration: 10
  start_delay: 0
```

Пример иконки:

```yaml
action: esphome.home_assistant_voice_0ab77d_matrix_show
data:
  message: ""
  icon: smile
  duration: 5
  start_delay: 0
```

У нативного действия ESPHome **все четыре поля обязательны**: для неиспользуемого
текста или иконки передавайте пустую строку. `icon: none` также означает отсутствие
иконки. Иконки: `smile`, `sad`, `heart`, `check`, `cross`, `bell`; поддерживаются
алиасы `🙂`, `🙁`, `❤️`, `✅`, `❌`, `🔔`.

`duration` — секунды, максимум 3600. Значение 0 прекращает показ сразу.
Короткий текст центрируется, длинный прокручивается; поддерживаются латиница,
кириллица, цифры и основная пунктуация, до 64 символов. При заполнении обоих
полей приоритет у иконки. Следующий вызов заменяет предыдущий показ.
После завершения экран возвращается к актуальному таймеру или часам.

### Необязательные поля, список иконок и задержка

В этом репозитории есть blueprint сценария
[`blueprints/script/matrix_show.yaml`](blueprints/script/matrix_show.yaml).
Он вызывает действие колонки напрямую; Custom-Dialog-UI для него не нужен.

1. Обновите прошивку колонки из `dev`: нативное действие теперь принимает
   четвёртый обязательный параметр `start_delay` (секунды, 0–3600).
   Добавьте `start_delay: 0` в существующие прямые вызовы ESPHome.
2. В Home Assistant откройте **Настройки → Автоматизации и сцены → Чертежи →
   Импортировать чертёж** и укажите:
   `https://github.com/mikhailhimei/home-assistant-voice-pe/blob/dev/blueprints/script/matrix_show.yaml`.
3. Создайте сценарий из чертежа **Voice PE — текст или иконка на матрице**.
   При создании выберите конкретную колонку (device ID) и укажите полное имя
   действия **этой же колонки**. Для каждой колонки создайте отдельный сценарий.
   Действие ESPHome уже адресное и не рассылает сообщение другим колонкам.
4. В автоматизации вызывайте созданный сценарий. У него `message` и `icon`
   необязательные, иконка выбирается из списка, `duration` по умолчанию 5 секунд,
   `start_delay` — 0 секунд. Пример (замените имя сценария на своё):

```yaml
action: script.voice_pe_matrix
data:
  device_id: f78b84553b463617269c25293950bb55
  message: "Привет"
  duration: 5
  start_delay: 2
```

Поле `device_id` в вызове можно пропустить: используется выбранная при создании
колонка. Если передать ID другой колонки, сценарий остановится с ошибкой,
не вызывая ESPHome. Он не перенаправляет вызов: для другой колонки нужен её сценарий.
Иконка выбирается из выпадающего списка в действии **созданного сценария**;
у прямого ESPHome-действия такого списка нет. `start_delay` по умолчанию равен 0.

Во время задержки часы и голос продолжают работать. Показ длится `duration`
секунд после задержки. Параллельные вызовы ожидают независимо; по окончании
задержки новый показ заменяет текущий. Если текст и иконка не заданы либо
`duration: 0`, после задержки возвращаются часы.

Нативное действие `esphome.…matrix_show` по ограничениям ESPHome сохраняет
обязательные параметры и обычное текстовое поле иконки. Нужный интерфейс
предоставляет созданный сценарий Home Assistant.

## Выключение экрана

Переключатель **Clock display (экран часов)** на странице устройства в Home Assistant выключает
всю матрицу через режим shutdown MAX7219: часы, таймеры и временные сообщения.
Голос, микрофон и световое кольцо работают независимо. Состояние переключателя
восстанавливается после перезапуска; выключенный экран не запускает стартовый тест.
В автоматизации выберите этот переключатель в действиях `switch.turn_off` /
`switch.turn_on`. При включении снова отображается актуальное состояние часов
или таймера. Яркость 0 у MAX7219 означает минимальную яркость, а не выключение.

## Микрофон

Переключатель **Mute** включён — микрофон выключен. В автоматизации
`switch.turn_on` включает приглушение, `switch.turn_off` снимает его.
Физический выключатель микрофона имеет приоритет.
Программное состояние Mute сохраняется после перезапуска и не сбрасывается
переключением физического выключателя. Включение Mute прерывает текущий диалог
и останавливает распознавание активационной фразы. Для возврата к прослушиванию
выключите Mute и физический выключатель; Home Assistant должен быть подключён.

## Радионяня: дополнительный модуль

Для радионяни **обязательно добавьте `modules/baby-monitor.yaml`** в список
`files` рядом с основным файлом. Пакет доступен в ветке `dev`:

```yaml
packages:
  voice_pe:
    url: https://github.com/mikhailhimei/home-assistant-voice-pe
    ref: dev
    files:
      - home-assistant-voice.yaml
      - modules/baby-monitor.yaml
    refresh: always
```

Остальные разделы вашего YAML (`substitutions`, `esphome`, `wifi`, `api` и другие)
сохраните. После добавления или удаления модуля заново соберите и установите
прошивку на колонку.

- **С модулем:** колонка может передавать звук с микрофона или воспроизводить
  звук другой колонки. Режим радионяни после включения питания выключен;
  подключение пакета само по себе не запускает передачу звука.
- **Без модуля:** голосовой ассистент, часы MAX7219 и обычное воспроизведение
  продолжают работать, но колонка не поддерживает радионяню ни как источник,
  ни как слушатель и не появляется в списке совместимых устройств радионяни.

Для пары установите модуль **на обе колонки**. Управление и прослушивание
с телефона доступны во вкладке **Радионяня** интеграции **HA Dialog UI** с
встроенным сервером радионяни. Отдельную интеграцию **Voice PE Monitor** для
этого устанавливать не нужно. IP сервера и ключ в YAML вручную не требуются.
При Docker bridge опубликуйте TCP-порт `8124:8124/tcp`; при `network_mode: host`
дополнительный проброс не нужен.

[Настройка HA Dialog UI и сценариев радионяни](https://github.com/mikhailhimei/ha-dialog-ui/blob/feat/baby-monitor-tab/docs/baby-monitor.md).
В текущей разработке эти изменения HA Dialog UI находятся в ветке
`feat/baby-monitor-tab` ([PR #1](https://github.com/mikhailhimei/ha-dialog-ui/pull/1)).
Старая инструкция [Voice PE Monitor](docs/baby-monitor.md) описывает отдельный
сервер и карточку; для встроенной вкладки HA Dialog UI они не нужны.

## Двойное нажатие и микрофон

Два быстрых нажатия верхней кнопки (пауза между ними не более 250 мс)
включают программный **Mute** и выключают микрофон. Одно нажатие при
программно выключенном микрофоне включает его обратно, не запуская диалог. Состояние видно в HA; событие `double_press` также сохраняется.
Физический выключатель имеет приоритет: при аппаратном отключении микрофон
не включится программно. При включённом **Disable physical controls** двойное
нажатие не выполняется.

## Звонки: отдельный модуль

Для звонков между колонками подключите **`modules/calls.yaml`** на обеих
Voice PE. Пакет радионяни для звонков не обязателен; можно оставить оба модуля.
Режим звонка не выключает Assist и поддерживает действия HA «позвонить»,
«ответить», «положить трубку» через отдельную вкладку HA Dialog UI.
При входящем звонке синее кольцо мигает целиком, при исходящем — вращается.
После ответа кольцо горит зелёным.
[Инструкция и ограничения экспериментального режима](docs/calls.md).

## Звучащий таймер и будильник

HA Dialog UI хранит расписание и подаёт команду `alert_start`. Прошивка сама
зацикливает сигнал до остановки. Стартовая громкость — 30%, плавное повышение
до 70% за 40 секунд; выше 70% автоматическое повышение не идёт.

Музыка текущего медиаканала ставится на паузу, сигнал играет в канале объявлений.
После остановки восстанавливаются громкость, mute и воспроизведение прежнего
медиаканала, если он играл перед сигналом. Поддержка паузы/возобновления зависит
от источника медиа; это не сохранение потока на диск. Звонок/радионяня при
срабатывании сигнала завершается и автоматически не возобновляется.

После остановки кнопкой или сценарием звучит короткое подтверждение `completed_sound`.
При остановке фразой активации звучит привычный сигнал `wake_word_triggered_sound`,
если включён **Wake sound**. Звуки используют восстановленную громкость; если до
сигнала был включён mute, подтверждение также заглушается.

Сигнал можно остановить верхней кнопкой, выбранной фразой активации
при включённом микрофоне либо сценарием HA:

```yaml
action: ha_dialog_ui.activity_stop
data:
  device_id: ID_КОЛОНКИ_В_HA
```

Также доступно нативное действие ESPHome `activity_stop` этой колонки.
Оно останавливает только звучащий таймер/будильник; расписание не удаляется.
Звонки это действие не затрагивает — для них используется `ha_dialog_ui.call_end`.
Во время сигнала новые звонки и радионяня не запускаются.

Стандартный сигнал встроен в прошивку. Для своей музыки HA передаёт временный
URL; если плеер не показывает воспроизведение более 10 секунд, колонка пробует
встроенный сигнал. Обнаружение сетевой ошибки также зависит от HTTP-таймаутов. Уже запущенный встроенный сигнал не зависит от соединения
с HA. Для срабатывания по расписанию HA всё ещё должен работать; после
перезапуска колонки воспроизведение сигнала автоматически не восстанавливается.

## Событие остановки сигнала

Прошивка публикует штатную сущность ESPHome **Alert stopped** (домен `event`).
Событие возникает только при фактической остановке звучащего сигнала, а не при
выключении будущего будильника или повторном вызове остановки уже тихой колонки.
Для сигнала используется только выбранная фраза активации, без отдельного
слова «стоп»; действие
`ha_dialog_ui.activity_stop` также сохранено и не затрагивает звонки.

Типы событий (`event_type`):

- `alarm_stopped_by_voice` / `timer_stopped_by_voice` — выбранная фраза активации;
- `alarm_stopped_by_button` / `timer_stopped_by_button` — верхняя кнопка;
- `alarm_stopped_by_script` / `timer_stopped_by_script` — действие HA/ESPHome.

Для различения будильника и таймера обновите и прошивку, и HA Dialog UI:
интеграция передаёт тип через `alert_start_v2`, сохраняя совместимость со старым
`alert_start`. Новый интерфейс/меню сценариев для этого не требуется.

Пример автоматизации после голосовой остановки будильника. Замените entity_id
на сущность **Alert stopped** своей колонки и укажите свой скрипт:

```yaml
alias: После голосовой остановки будильника
triggers:
  - trigger: state
    entity_id: event.home_assistant_voice_0ab77d_alert_stopped
conditions:
  - condition: template
    value_template: >-
      {{ trigger.from_state is not none
         and trigger.from_state.state != 'unavailable'
         and trigger.to_state is not none
         and trigger.to_state.state not in ['unknown', 'unavailable']
         and trigger.to_state.attributes.event_type == 'alarm_stopped_by_voice' }}
actions:
  - action: script.ВАШ_СКРИПТ
mode: single
```

Для таймера замените тип на `timer_stopped_by_voice`. Триггер должен отслеживать
саму сущность, а не только атрибут `event_type`, чтобы повторные остановки того
же типа тоже запускали автоматизацию. Событие доставляется через подключение
ESPHome к HA; офлайн-события не сохраняются в очереди для последующей доставки.
